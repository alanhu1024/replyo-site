Replyo 隐私说明

更新日期：2026 年 10 月 30 日 — 版本 0.3.15

版本适用范围：本次修订说明 Replyo 0.3.15 所包含功能的数据处理方式。具体功能取决于你安装的版本；不支持 AI、工作台、关注列表检查或账号卡片的旧版本（包括 0.1.4）不会因本说明更新而新增这些处理，也不会向所选 AI 服务商发送帖子或草稿。0.3.14 的 AI 功能仅连接 DeepSeek；本政策更新不会为旧版新增服务商。当前公开版本以 Chrome 商店显示为准。

Replyo 是独立浏览器插件，可在 X 通知中的部分回复旁显示其直接回复的原文，并在首页和帖子详情页显示可获取的作者公开粉丝数。插件还提供本地回复草稿、互动工作台、可选的 AI 回复建议、账号信息卡片，以及自己的正在关注、关注者和认证关注者列表检查。本说明介绍这些功能如何处理信息。联系邮箱：alanhu1024@gmail.com。

Replyo 处理哪些信息

你阅读数据使用提示并启用 Replyo 后，插件会读取浏览器中支持的 X 页面信息：帖子和回复文字、作者昵称与用户名、X 已加载页面数据中可用的作者及回复者公开粉丝数、帖子标识符和链接，以及回复与直接原文的关系。粉丝数来自 X 已经加载的数据，Replyo 不会为此额外请求个人主页。插件还会从导航中的个人资料链接读取当前 X 账号用户名，用于在切换账号时隔离缓存。

这些信息包含网站内容，以及昵称、用户名等个人信息。商店中的“网页历史记录”披露仅涉及获取上下文所需的具体 X 帖子链接；“个人通信”披露仅涉及已登录账号能够访问的帖子和回复。原文预览、粉丝徽章和手动草稿编辑在本地处理；可选的 AI 处理见下文。上述信息不会发送给开发者。Replyo 不读取 X 私信、密码或身份验证 Cookie，不读取 Chrome 历史记录数据库，不处理其他网站内容，也不跨网站跟踪活动。

为什么使用这些信息

Replyo 用这些信息识别回复的直接原文，显示原文文字、作者及双方可用的公开粉丝数，在首页和详情页的帖子旁显示可用粉丝数，复用近期上下文，并避免混淆不同登录账号的信息。使用草稿面板或工作台时，所选帖子及可用的直接上文也用于帮助你准备回复、保存待办和重新查看自己的草稿。账号卡片和关注列表检查还会使用可获取的作者信息及明确的关注关系，展示下文所述的有限信息。Replyo 不将这些信息用于广告、用户画像、模型训练或无关用途。

加载缺失原文

已有缓存的上下文可以自动显示。缺失时默认由你手动加载。你选择加载后，Replyo 可能临时打开一个后台 X 标签页，读取相关原文页面。你也可以在插件面板中单独开启自动加载，每次只加载一个页面。完成、失败或超时后，如果标签页没有被你接管，且仍停留在请求的帖子或 X 登录页面，Replyo 会关闭自己创建的加载标签页。你接管或跳转到其他位置的标签页会保留。

这些请求通过 HTTPS 从浏览器直接发送到 X，使用你已有的 X 登录状态。X 可能依照自身规则接收请求页面、网络信息等常规访问数据；这些访问也可能受浏览器正常历史记录机制影响。Replyo 不会复制或将你的登录凭据发送给开发者。

回复草稿与互动工作台

在支持的 X 回复弹框和帖子详情回复区，Replyo 可以提供草稿面板，并读取已确认的所选帖子及已经可用的直接上文。它不会为此扫描完整对话历史或额外打开页面，不会分析图片、视频或嵌入引用帖的内容。界面会提示上下文可能缺失。

你可以自己写草稿，也可单独配置下文的 AI 功能。点击填入按钮会将选中的文字放入已确认的 X 回复区，不会点击 X 的发送按钮。如果回复区已有内容，覆盖需由你另行明确操作。X 可能按照自身规则处理输入其编辑器的内容，包括草稿处理。

你可以主动将草稿及所选帖子保存到本地工作台，并标记为待处理、稍后或已处理。这些标记代表你的工作记录，不代表 Replyo 已确认 X 发布成功。你也可以手动填写日期和粉丝总数，查看记录日期之间的变化。Replyo 不自动采集这些记录，也不判断某次互动导致了粉丝增长。

账号信息卡片与关注关系徽章

在可获取的粉丝数旁，Replyo 可以显示帖子作者与当前登录账号之间的明确关系：已关注你、你已关注或互相关注。点击徽章可打开账号卡片，查看作者昵称、用户名、可用的粉丝总数、关注总数及关注关系。这些信息仅来自 X 已加载且身份匹配的数据，不额外请求个人主页。证据缺失或冲突时，关系保持待确认。这些针对当前登录账号的关系标记仅保存在当前页面内存中，不写入上下文缓存、不导出，也不发送给所选 AI 服务商或开发者；页面切换、账号切换或停用 Replyo 时会清除。公开作者标识和关注总数可以随原文上下文保存在已有上限与期限的会话缓存中；缓存的公开数字最多有效 15 分钟，针对当前账号的关系标记不会从该缓存恢复。

本版本没有接入 X API 服务，不会为互关粉丝分析发起 X 官方 API 请求。接入前，卡片会显示分析不可用；Replyo 不会根据粉丝数、关注数或不完整的页面列表推算百分比。计划中的指标表示分析时某账号粉丝中与其互相关注者的占比，不是历史回关率，也不是预测。未来如启用外部分析，需要另行接入，并在开始请求前更新披露。

关注列表关系检查

在自己的 X 正在关注、关注者或认证关注者页面主动选择“开始检查”后，Replyo 只读取 X 已渲染的账号行：昵称、用户名、可用的数字用户标识，以及明确的关注和被关注状态。它会显示互相关注或待确认，在正在关注列表中识别未回关你的账号，在关注者和认证关注者列表中识别你尚未回关的账号。你可以在本地筛选已检查的结果。认证关注者的结果仅覆盖该标签，不代表全部关注者；缺失关系数据不会被当作“未关注”。检查不会自动滚动列表、加载额外个人主页、调用关注关系 API、关注或取消关注账号，也不向所选 AI 服务商或开发者发送这些记录。如果你点击“去回关”，Replyo 会滚动到并突出显示仍在页面中的对应 X 原生关注按钮，或为你打开该账号的 X 主页。是否关注由你决定，并由你点击 X 自己的按钮完成。仅定位或打开主页不会被标记为关注成功；只有重新读取到身份匹配的页面数据后，才会显示关系变化。结果仅反映已加载页面中的数据，不是完整或持续刷新的账号审计。

检查结果只保存在当前 X 页面的内存中，上限为 2,000 个账号。切换列表标签、离开这些列表页面、切换登录账号、停用 Replyo、刷新或关闭页面都会清除结果；暂停检查会保留当前结果，直到发生上述情况。明确选择的显示语言可保存在本地，关注关系记录不写入插件存储，也不导出。

可选的 AI 回复建议

0.3.15 支持 DeepSeek、OpenAI、OpenRouter 和硅基流动（中国区端点），同时仅启用一份配置。Key 与所选服务商和模型绑定，限制请求内置的 HTTPS 地址。切换服务商会清空未保存的 Key，并重新要求同意数据使用；保存新配置会清除旧凭据并取消正在进行的请求。旧版 Key 仅归属于 DeepSeek。OpenRouter 可能把生成内容转交给所选模型的上游服务商，双方的数据留存及隐私规则均适用。测试不保证余额及实际生成权限。

只有你在插件设置中输入所选服务商的 API Key、同意 AI 数据使用提示，并授予所选服务商的 HTTPS 域名访问权限后，才可使用 AI。只有你主动点击“生成候选”，后台脚本才会通过 HTTPS 将所选帖子文字、可用的准确直接上文、你输入的想法及内置回复类型指引直接发送到所选 AI 服务商。帖子文字最多 8,000 字符，上文最多 4,000 字符，输入想法最多 2,000 字符。图片、视频、无关帖子、已保存的待办集合、粉丝数、本地账号标识和 X 登录凭据不会作为独立字段发送；所选文字中本身包含的姓名或其他个人信息仍可能被发送。

API Key 仅通过请求的授权标头发送到所选 AI 服务商的固定 API 地址。Replyo 不通过开发者服务器转发请求，也不会将密钥暴露给 X 页面中的内容脚本。所选 AI 服务商 会收到请求内容、API 凭据及 IP 地址等常规网络信息，并按其自己的条款和隐私规则处理。Replyo 不承诺所选 AI 服务商零保留，也不能独立控制其对 API 数据的使用。调用费用由你的所选 AI 服务商账户承担。

每次生成最多提供四个不同类型的回复候选，依据所选文字、你输入的想法和内置回复类型目录选择表达方式。Replyo 不会查看或学习你的历史评论、互动效果或已保存的草稿来建立个人写作画像。

“测试连接”只请求所选服务商模型列表，OpenRouter 还会校验 Key 信息，不发送帖子或生成回复。保存密钥不会发起生成。候选以纯文本展示，选择候选只会改变本地草稿，不会自动保存待办或发布。取消会停止本地处理和连接，但无法撤回已经发送的数据，也不能保证所选 AI 服务商不对已完成的处理收费。Replyo 不自动重试付费生成请求。

存储与保留期限

  • API Key 和 AI 同意记录：默认保存在仅可信插件上下文可访问的 chrome.storage.session 中；重启浏览器，或停用、重新加载、更新插件后会清除。只有你选择“在此浏览器中记住”，才会改为保存在插件自己的 IndexedDB 中，直到你移除密钥或卸载插件。Replyo 不通过 Chrome Sync 同步密钥，不把它放进草稿导出或日志，也没有对持久化存储另行加密。切换保存方式会移除旧位置的凭据；删除或更换密钥会取消正在生成的请求。
  • 偏好设置：启用状态、自动加载选项，以及你明确选择的 AI 设置页、工作台、关注检查和功能介绍页语言保存在 chrome.storage.local 中，直到你修改或卸载插件。Replyo 不通过 Chrome Sync 同步它们；语言偏好不包含 API 凭据。
  • 上下文缓存：近期帖子上下文保存在 chrome.storage.session，按识别到的 X 账号隔离。原文作者的公开粉丝总数和关注总数与帖子上下文一同受缓存上限约束，并设有 15 分钟的数字有效期。读取并保存新获取的可用数字会重新计算期限；保留下来的旧粉丝数沿用原期限，只能在作者相同且仍有效时复用。过期数字不会复用，并在后续缓存操作中清除。首页、详情页作者信息及回复者粉丝数只存在当前页面内存中，不写入插件存储，Replyo 不建立独立个人资料库。每次从 X 已加载数据中读取并保存帖子时，该记录的 15 分钟期限会重新计算；复用现有 Replyo 缓存不会延长期限。过期记录不会复用，会在下一次缓存操作时移除；没有保证恰好 15 分钟物理删除的后台计时器。缓存总上限为 300 条和 4 MiB，也可能提前被移除；浏览器会话结束后清除。
  • 临时加载状态：加载期间，会话存储还记录插件创建的标签页标识、请求的原文标识，以及标签页是否被接管。这些数据用于安全清理，加载结束后移除，不构成其他标签页清单。
  • 会话协调：一个数字形式的缓存版本计数器用于同步清缓存和暂停状态，不含帖子或账号标识，会在浏览器会话结束后清除。
  • 工作台临时预览：从帖子打开工作台时，会在 chrome.storage.session 中建立按账号隔离的临时预览，包含该帖子、可用直接上文和上下文提示。上限为 20 条、总计 4 MiB、30 分钟。打开预览不等于永久保存待办。
  • 保存的待办与草稿：只有主动保存时，所选帖子、可用直接上文、账号用户名、草稿、回复方向、状态和时间戳才会写入 chrome.storage.local。每个账号最多 100 条待办，最后一次保存 30 天后过期；更改状态也会保存待办，预览或读取不会延长期限。
  • 粉丝记录：按账号保存你手动输入的每日粉丝总数，保留包括当天在内的 90 个自然日。待办和粉丝记录总上限为 4 MiB，不会发送给开发者或通过 Chrome Sync 同步。空间达到上限时，会要求你移除记录，而不是静默丢弃已保存草稿。
  • 过期清理：过期工作台记录会在后续工作台操作中排除并清理，没有保证恰好到期时物理删除的后台计时器。未主动保存的临时草稿留在当前页面，关闭页面或回复编辑器时可能丢失。
  • 清除缓存：你随时可以从插件面板清除原文缓存；这不会删除工作台待办或粉丝记录。你可另行删除单条待办或清除某账号的工作台记录。这些操作不会删除 X 页面中的内容。

Replyo 只保存你主动选择的待办上下文，不保存完整对话档案；开发者服务器上没有副本。

共享与开发者访问

Replyo 没有开发者运营的后台、使用统计服务或广告跟踪器。插件不会向开发者发送或出售缓存帖子、待办上下文、草稿、账号用户名、粉丝记录、偏好或 API Key。外部处理仅限于加载上下文所需的直接 X 请求，以及上述由你主动发起的可选 AI 请求。Replyo 不使用你的内容训练模型。

如果你主动给支持邮箱发邮件，开发者会收到你的邮箱地址、邮件内容及主动附加的文件；邮件提供商也会处理该通信。信息仅用于回复请求和排查问题，在该用途和适用义务所需期间保留，并在不再需要保留时按请求删除。请勿发送密码、身份验证 Cookie 或私密帖子内容。客服不需要访问你的 X 账号。

你可以如何控制

你可以启用或停用 Replyo、选择手动或自动加载、清除上下文缓存或卸载插件。停用会停止新的 X 页面处理并清除缓存，但已保存的工作台记录会保留到你删除或其过期；暂停不等于删除工作台。卸载会移除插件本地设置与存储。你也可在 AI 设置中删除密钥，并在浏览器中撤销所选服务商的可选站点权限。隐私问题或支持邮件请发至 alanhu1024@gmail.com。

安全与限制

X 功能需要访问 https://x.com/*。https://api.deepseek.com/*、https://api.openai.com/*、https://openrouter.ai/*、https://api.siliconflow.cn/* 权限均为可选，仅在设置中连接或测试时请求所选服务商的域名。Replyo 使用安装包内代码和固定模型服务地址。上下文缓存和持久化凭据没有被 Replyo 另行加密；能访问你的浏览器或设备的其他人或软件，可能访问本地存储的信息。源内容及其可用性由 X 决定。

Chrome 商店 Limited Use 要求

Replyo 对信息的使用遵守 Chrome Web Store 用户数据政策，包括 Limited Use（有限使用）要求。为原文预览、粉丝徽章、账号信息卡片、关注列表关系检查、草稿、待办和手动粉丝记录处理的信息，仅用于这些已披露功能，不出售，不用于个性化广告，也不用于判断信用状况或贷款资格。

本说明页面与变更

安装包中的隐私页没有脚本、外部字体或跟踪资源。访问此网站上的隐私说明时，浏览器会联系网站托管服务商；这与插件本身的运行是分开的。本网页的语言切换不会保存偏好或向外部发送信息。

Replyo 变化时，本说明可能更新，顶部日期标记最近一次修订。数据处理方式有重大变化时，会在开始新处理之前通过插件披露，并在需要时取得同意。

Replyo 与 X Corp. 无关联，也未获得其背书。

Replyo Privacy Policy

Last updated: October 30, 2026 — version 0.3.15

Version scope: This revision describes the features included in Replyo 0.3.15. Feature availability depends on the installed version. Older versions without AI, workspace, Following-check or account-card features, including 0.1.4, do not gain those processing activities from this policy update and do not send posts or drafts to AI providers. Version 0.3.14 connects AI only to DeepSeek; updating this policy does not add providers to an older build. The Chrome Web Store listing identifies the currently published version.

Replyo is an independent browser extension that shows the directly replied-to post beside supported replies in X notifications, and available author follower counts on the X Home timeline and post detail pages. It also provides a local reply-draft panel, an interaction workspace, optional AI-provider reply suggestions, account information cards and checks of your own Following, Followers and Verified Followers lists. This policy explains how Replyo handles information. Contact: alanhu1024@gmail.com.

What Replyo processes

After you review the data-use notice and enable Replyo, it reads information from supported X pages in your browser: post and reply text, author display names and usernames, public follower counts of post authors and repliers when available in X's loaded page data, post identifiers and links, and the relationship between a reply and its direct parent. Follower counts come from data X has already loaded for the page; Replyo makes no additional profile requests to obtain them. It also reads the current X account handle from the navigation profile link to keep context caches separate when accounts change.

This includes website content and personal information such as names and usernames. For the extension's context feature, the Web history disclosure covers only the specific X post links needed for context, and the Personal communications disclosure covers only posts and replies the signed-in X account can access. Context previews, follower badges and manual draft editing are processed locally. Optional AI-provider processing is described separately below. This information is not sent to the developer. Replyo does not read X direct messages, your password, or authentication cookies. It does not read Chrome's history database, process content from other websites, or track activity across them.

Why it uses this information

Replyo uses this information only to identify a reply's direct parent, display its text and author together with available public follower counts for the original author and replier, show available author follower counts beside displayed posts on Home and post detail pages, reuse recent context, and avoid mixing information between signed-in accounts. When you use the draft panel or workspace, it also uses the selected post and its available direct-parent text to help you write a reply, save a task, and revisit your own drafts. Account cards and Following checks use the available author data and explicit relationship states to show the limited information described below. It does not use this information for advertising, profiling, AI training, or unrelated purposes.

Loading missing context

Previously cached context can be displayed automatically. If context is missing, manual loading is the default. When you choose to load it, Replyo may open a temporary inactive X tab to read the relevant parent page. You can separately enable automatic loading in the popup. It loads one page at a time. It closes its own loading tab after completion, failure, or timeout if you have not taken it over and it is still on the requested post page or has been redirected to an X sign-in page. Tabs you take over or navigate elsewhere are kept open.

These page requests go directly from your browser to X over HTTPS using your existing X session. X may receive normal website request information, such as the requested page and network information, under its own practices. Normal browser history behavior may also apply to these visits. Replyo does not copy or send your login credentials to the developer.

Reply drafts and the interaction workspace

On supported X reply dialogs and post-detail reply editors, Replyo provides a draft panel for the selected post. It reads only the identified post and its directly related parent if already available. It does not scan your full conversation history or open extra pages for this panel. Media contents and embedded quoted posts are not analyzed. Missing context is identified in the interface.

You can write drafts yourself or separately configure the optional AI-provider feature described below. Clicking the insert control puts the chosen text in the identified X reply editor; it does not click X's send button. If that editor already has text, replacing it requires a separate explicit action. X may process content entered into its editor under its own practices, including its draft handling.

You can choose to save a draft with its selected post to the local workspace and mark it as to-do, later, or done. These labels describe your own workflow, not confirmed X publishing events. You can also manually enter a date and follower count to track change between your recorded dates. Replyo does not collect these records automatically or claim that an interaction caused follower growth.

Account information cards and relationship badges

Beside available follower counts, Replyo can show the displayed author’s explicit relationship with the currently signed-in account: following you, followed by you, or mutual. Clicking a badge opens an account card with the author’s name, handle, available follower/following totals, and relationship. This uses only identity-matched data already loaded by X, without extra profile requests. Missing or conflicting evidence remains unknown. These viewer relationship flags are kept only in current-page memory and are not saved to the context cache, exported, or sent to an AI provider or the developer. They are cleared when the page changes, the account changes, or Replyo is disabled. Public author identifiers and following totals may accompany parent context under the existing bounded session-cache policy. Cached public counts expire after at most 15 minutes; viewer-specific relationship flags are never restored from that cache.

This version has no connected X API provider and makes no official X API requests for mutual-follower analysis. The card marks analysis as unavailable until that integration is configured. It does not calculate a percentage from follower/following totals or incomplete page lists. The planned metric describes the share of an account’s followers it also follows at the time of analysis; it is not a historical follow-back rate or a prediction. Enabling any future external analysis will require a separate integration and updated disclosures before requests start.

Following relationship checks

When you choose Start checking on your own X Following, Followers or Verified Followers page, Replyo reads only the user rows that X has already rendered: display names, handles, available numeric user identifiers, and explicit following/followed-by states. It shows mutual or unknown relationships, identifies people who do not follow you back in Following, and identifies followers you have not followed back in Followers and Verified Followers. You can filter the checked results locally. Verified Followers results cover only that tab, not all followers. Missing relationship data is not treated as a negative. The check does not automatically scroll the list, load extra profiles, call a relationship API, follow or unfollow accounts, or send these records to an AI provider or the developer. If you choose “Go to follow back”, Replyo scrolls to and highlights a matching native X follow control that is still on the page, or opens that account’s X profile for you. You decide whether to follow and click X’s own control yourself. Navigation alone never marks a follow as successful; a relationship change is shown only after matching page data can be read again. Results describe the loaded page data, not a complete or continuously refreshed account audit.

Following checks stay only in the current X page memory, with a limit of 2,000 accounts. Switching list tabs, leaving these list pages, changing the signed-in account, disabling Replyo, refreshing or closing the page clears the results. Pausing checks keeps the current results until one of those events. The explicit display-language preference can be stored locally; relationship records are not written to extension storage or exported.

Optional AI-provider reply suggestions

Version 0.3.15 supports DeepSeek, OpenAI, OpenRouter and SiliconFlow (China endpoint). One configuration is active at a time. Each key is bound to its selected provider and model, with requests restricted to packaged HTTPS endpoints: api.deepseek.com, api.openai.com, openrouter.ai or api.siliconflow.cn. Selecting a provider in settings does not send or reuse a previous provider’s key. Changing provider clears the unsaved key field and asks for new consent. Saving a replacement removes the previous stored credential and cancels active requests. Legacy DeepSeek credentials remain assigned to DeepSeek only.

OpenRouter is a routing service: it may forward the generation contents to the upstream model provider you select. Both its and that upstream provider’s terms and privacy practices apply. Replyo cannot guarantee their data retention. Choose a model and service you trust before consenting. Test connection does not generate text or verify that your balance and generation permissions are sufficient.

AI is off until you enter your own API key for the selected provider in the extension settings, accept the AI data-use notice and grant access to the selected provider’s HTTPS origin. When you explicitly choose Generate ideas, the extension background worker sends the selected post text, the available exact direct-parent text, your entered thoughts and built-in reply-type guidance directly to the selected provider over HTTPS. Long post text is limited to 8,000 characters and parent text to 4,000; your entered thoughts are limited to 2,000. Photos, video, unrelated posts, saved tasks, follower counts, local account identifiers and X authentication credentials are not included as separate input fields. Names or other personal information present within the selected text can be included.

Your API key is sent in the authorization header only to the fixed endpoint for your selected provider. Replyo does not route requests through a developer server or expose the key to its X-page content scripts. The selected provider receives the request contents, your API credentials and normal network information such as your IP address. Its own terms and privacy practices govern that processing; Replyo does not promise that a provider has zero retention or independently control its use of API data. Usage charges are paid by your selected provider account.

Generation can return up to four varied reply candidates, chosen using the selected text, your notes and the built-in reply-type catalog. It does not inspect or learn from your past comments, engagement results or saved drafts to create a personal writing profile.

Test connection requests the selected provider’s model list (and, for OpenRouter, its authenticated key-information endpoint), without sending a post or generating a reply. Saving a key does not send a generation request. Candidate text is shown as plain text; selecting it changes only your local draft. No candidate is automatically saved or published. Cancellation stops local processing and the connection, but cannot recall data already transmitted or guarantee that your provider will not charge for work already done. There are no automatic paid retries.

Storage and retention

  • API key and AI consent: By default the key and consent flag are held in chrome.storage.session, restricted to trusted extension contexts. They are cleared when the browser restarts or the extension is disabled, reloaded or updated. Only if you choose Remember in this browser are they instead stored in the extension's own IndexedDB until you remove them or uninstall Replyo. The extension does not synchronize credentials through Chrome Sync, include them in draft exports or log them. Persistent storage is not separately encrypted by Replyo. Changing the storage mode removes the old credential location. Removing or replacing the key cancels active generation requests.
  • Preferences: The enabled and automatic-loading settings and your explicit AI-settings, workspace, Following-check and About-page language choices are stored in chrome.storage.local. They remain until you change them or uninstall Replyo; they are not synchronized through Chrome Sync by the extension. Language preferences do not contain API credentials.
  • Context cache: Recent post context is stored in chrome.storage.session and separated by the identified X account. Parent-author public follower and following totals are stored with the post context under the same cache limits and a 15-minute count-validity period. Reading and saving fresh available counts starts or restarts that period. A retained earlier follower count keeps its previous deadline; it can be reused only for the same author while it remains valid. Expired counts are not reused and are cleared during subsequent cache operations. Home and post-detail author metadata and replier follower counts remain only in the current page's memory and are not written to extension storage. Replyo does not create a separate profile database. Each time Replyo reads a post from X's loaded page data and saves it, that record's 15-minute validity period starts or restarts. Reusing an existing Replyo cache entry does not extend the period. Expired records are not reused and are removed at the next cache operation. There is no background timer guaranteeing physical deletion at exactly 15 minutes. The cache is limited to 300 records and 4 MiB overall, and can be evicted earlier. It is cleared when the browser session ends.
  • Temporary loading state: While loading context, session storage also records the extension-created tab identifier, the requested parent-post identifier, and whether the tab has been taken over. These records support safe cleanup, are removed when loading ends, and do not form a list of your other tabs.
  • Session coordination: A numeric cache-revision counter synchronizes cache clearing and pausing across extension components. It contains no post content or account identifier and is cleared when the browser session ends.
  • Workspace previews: Opening a post in the workspace creates a temporary, account-scoped preview in chrome.storage.session containing that selected post, its available direct parent, and context warnings. Previews are capped at 20 entries, 4 MiB overall, and 30 minutes. Opening a preview does not save a permanent task.
  • Saved tasks and drafts: Only when you choose Save, the selected post and available direct parent, account handle, your draft, intent, status, and timestamps are saved in chrome.storage.local. Each account can hold up to 100 tasks. Tasks expire 30 days after their most recent save. Changing status also saves the task. Previewing or reading a task does not extend this period.
  • Follower progress: Manually entered daily follower totals are kept locally by account for 90 calendar days, including today. Tasks and progress together are limited to 4 MiB. Replyo does not send them to the developer or synchronize them through Chrome Sync. At capacity, it asks you to remove records instead of silently evicting your saved drafts.
  • Expiry: Expired workspace records are excluded and cleaned during subsequent workspace operations. There is no background timer guaranteeing physical deletion at the exact expiry time. Temporary draft text that you have not saved stays in the current page and may be lost when that page or reply editor closes.
  • Clear cache: You can delete the current context cache from the Replyo popup at any time. This does not delete saved workspace tasks or progress. You can remove individual tasks or clear an account's workspace separately. Content on an open X page remains governed by X and is not deleted by these actions.

Replyo stores only the task context you explicitly save, not a full archive of your conversations. No copy is kept on a developer server.
